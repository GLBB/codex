# Agent Trace 文档约定

适用于本目录及子目录的协议设计、审阅与编辑。

## 设计依据

- 优先遵循文档固定版本的 OpenTelemetry GenAI 及相关领域规范。标准已有且语义一致的属性直接复用，不改变其含义。
- 规范未定义且有明确观测需求时，才增加 `corojaw.*` 属性。标准属性允许扩展取值时，先考虑定义取值，避免另建语义重复的属性。
- 通用部分只定义共性规则；各类 span 定义自己的属性、错误分类与映射。已有领域规范时引用该规范。
- 区分 span 元数据、status、属性和日志事件，不将 status description 误列为业务属性。

## 表达与组织

- 简洁、直接，围绕“字段表示什么、何时填写、取什么值”写协议。优先使用短列表和属性表。
- 每类 span 按调用边界与父子关系、属性定义逻辑、属性表、失败分类组织；只保留适用内容。
- 避免重复通用约定和添加冗长的解释性规则。必要的统计范围、单位和采集条件写入字段说明。
- 区分实际执行统计与本次生效的配置限制。
- 未确认的机制以引用块 `> TODO：…` 放在相关 span 标题下，不提前引入属性或把设计假设写成既定能力。跨 span 的问题放在相关通用章节。
- 不因某项信息可由轨迹记录，就默认 trace 无需表达；结合筛选、统计和排障需求判断，并明确尚未确定的取舍。

## 协作与变更

- 用户要求先输出方案供 review 时，先给草案和与当前版本的差异；仅落地用户已明确要求的改动。
- 删除或新增属性时说明字段变化及原因，不静默扩大或缩小协议范围。
- 用户要求更新时直接编辑文档；提交仅在用户要求时执行。
