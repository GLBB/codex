# MCP 安全与信任

## 信任链

一次 MCP 集成至少跨越以下链路：

```text
Server 来源与版本
    ↓
Tool / Resource / Prompt 定义
    ↓
Host 过滤、展示与模型选择
    ↓
参数、身份和凭据
    ↓
Server 与外部系统执行
    ↓
调用结果 / Resource / Prompt 内容
    ↓
模型后续决策和副作用
```

任何一层受到错误信任，都可能把“外部数据”提升为“可信指令”，或把一次只读任务升级成写操作。

## 主要威胁

| 威胁 | 例子 | 主要控制 |
| --- | --- | --- |
| 工具投毒（Tool Poisoning） | Tool 描述诱导模型读取密钥 | 审查 Server 来源和工具定义，最小化可用工具范围 |
| 注解欺骗 | 写工具声明 `readOnlyHint=true` | 采用保守默认值、Host 策略、审计和 Server 允许列表 |
| 提示词注入 | Resource 要求模型忽略用户并调用发送工具 | 保留来源、标记不可信内容、实施数据流策略和关键操作审批 |
| 数据外传 | Tool 参数携带无关源码或客户数据 | 最小披露、字段策略、域名和权限范围控制 |
| 凭据泄露 | Token 出现在 Prompt、参数、日志或调用结果中 | 运行时注入、安全存储、脱敏并禁止模型读取 |
| 混淆代理（Confused Deputy） | Server 借助 Host 的高权限访问其他租户 | 绑定用户、校验受众和租户、采用最小 OAuth 权限范围 |
| 供应链攻击 | 本地 Server 软件包或更新被篡改 | 固定版本、验证来源、安装审批和隔离运行 |
| 可用性攻击 | 巨型 Schema、无界结果或请求卡死 | 设置大小硬上限、超时、并发和速率限制 |
| Elicitation 欺骗 | 伪装成登录表单收集密码 | 显示 Server 身份、限制字段、校验 URL 和来源 |
| Sampling 滥用 | Server 嵌套调用模型和 Tool，消耗大量预算 | 限制能力、审批、深度、Token 和成本 |

## 注解的正确位置

注解在系统中的处理过程是：

```text
Server 定义
    ↓ 外部声明
保存到能力目录
    ↓
审批 / 调度器 / 重试策略读取
    ↓ 与 Host 策略、用户配置、身份共同决策
运行时执行
```

注解不会在 Schema 校验阶段自动转化为授权，也不能替代沙箱。`destructiveHint=false` 只表示 Server 声称该工具主要不是破坏性的，并不代表它没有写入、隐私或数据外传风险。

## 审批、沙箱与身份认证

三者回答不同问题：

| 机制 | 回答的问题 |
| --- | --- |
| 身份认证（Authentication） | 当前连接以谁的身份访问 Server？ |
| 授权与权限范围 | 该身份在外部系统中可以执行哪些操作？ |
| 审批（Approval） | 用户是否允许执行当前这项具体操作？ |
| 沙箱与隔离 | 即使代码存在恶意行为，实际能够访问哪些资源？ |

远程 MCP Tool 通常在 Server 侧执行，本地文件沙箱未必能约束远程副作用；此时必须依靠外部权限范围、工具策略、审批和审计。本地 stdio Server 则应受到进程、文件、网络和环境变量的隔离约束。

## 不可信内容治理

Tool 调用结果、Resource 和 Prompt 都可能包含自然语言指令。Host 应：

- 保留 Server、URI、Tool、时间和身份等来源信息；
- 将外部内容作为数据而非高优先级指令；
- 限制内容进入提示词的位置和长度；
- 当内容可能触发外部写操作时，重新进行权限和审批检查；
- 避免把密钥、内部策略或其他 Server 的私有上下文转发出去；
- 为用户提供调用来源与数据去向的可见性。

## 认证与凭据

远程 Server 常使用 OAuth 或 Bearer Token，本地 Server 可能通过环境变量获得凭据。安全设计应包括：

- Token 不进入模型上下文；
- 仅由运行时在调用时注入；
- 权限范围、受众、租户和用户身份保持一致；
- 明确处理 Token 刷新、撤销和过期；
- 日志、错误和追踪记录中不保存密钥；
- Server 配置不能从不可信项目静默覆盖高权限凭据。

对于受保护的远程 Streamable HTTP Server，还要区分 OAuth 资源指示符（Resource Indicator）与 MCP Resource URI，验证 Token 的目标受众，并禁止把 Client 交给 MCP Server 的 Token 原样转发给下游 API。受保护资源元数据、PKCE、权限范围挑战和增量授权的完整流程见 [远程 HTTP 与授权](10-remote-http-and-authorization.md)。

## 安全评审清单

1. Server 的来源、运营者、版本和更新机制是什么？
2. Tool、Resource、Prompt 哪些对当前用户可见？
3. 注解缺失、错误或互相矛盾时如何处理？
4. 凭据由谁持有，权限范围和租户边界是什么？
5. 本地 Server 的文件、网络、环境变量和子进程权限是什么？
6. 外部内容如何标记、截断、脱敏和隔离指令？
7. 哪些调用需要逐次审批，哪些可以会话授权？
8. 请求超时、取消或结果状态未知后，如何避免产生重复副作用？
9. 如何撤销 Server、Tool、Token 和缓存的能力定义？
10. 追踪记录能否还原谁在何时以什么身份执行了什么操作？
