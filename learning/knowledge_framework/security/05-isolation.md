# Isolation：限制“即使失控也能做什么”

| 机制 | 主要保护 | 不能单独解决 |
| --- | --- | --- |
| Worktree | 代码修改互不覆盖、便于审查 | 恶意进程、网络和宿主机访问 |
| Sandbox | 文件、进程、网络和系统调用范围 | 外部 SaaS 已发生的副作用 |
| Container | 进程、文件系统和依赖环境隔离 | 内核漏洞、错误挂载、凭据滥用 |
| VM | 更强的内核和宿主隔离 | 用户批准错误、远程服务自身的权限 |

分析任务可以在临时 Worktree 和受限执行器中运行；源码只读挂载，构建缓存单独可写；网络默认关闭，仅批准访问依赖镜像；SSH Agent、云凭据不透传；完成后销毁临时环境。提交文档则在受控 Broker 中再次执行 Policy 和 Approval。

## 实践

画出本地 Agent、执行器、容器、外部 API 和宿主机的边界。为每条边界写一个验证：访问工作区外文件、访问未批准域名、读取环境变量、启动超额资源进程。记录预期是拒绝、截断还是暂停。
