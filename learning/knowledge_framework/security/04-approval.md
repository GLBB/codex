# Approval：何时必须停下来询问

Approval 是有身份的决策者对一项具体动作、具体参数、具体范围和具体风险作出的授权。它不能替代 Policy：被 Policy 禁止的动作不能靠一次随意点击放行。

| 等级 | 例子 | 建议控制 |
| --- | --- | --- |
| 低 | 读取普通项目文件、运行只读检查 | 默认允许，记录调用 |
| 中 | 修改工作区、安装依赖、访问内部 API | 会话授权或逐次审批 |
| 高 | 推送代码、发消息、创建订单、发布 | 显示完整参数，逐次审批 |
| 极高 | 生产变更、删除数据、读取 Secret | 明确人工审批、双人或变更流程 |

审批界面至少展示：谁发起、Agent 和工具身份、将访问什么数据、目标系统、具体参数、预期副作用、有效期、可撤销方式。只显示“允许执行命令”是不合格的审批。

“本次允许修改 `src/` 下的两个文件”比“本次允许写文件”更安全；审批后参数发生变化，必须重新审批。

## 实践

设计一个审批卡片，内容是“把分析报告提交到文档系统”。要求审批者能看见文档目标、报告摘要、可能包含的敏感字段、调用身份和撤销路径。再写出用户拒绝、审批超时和参数被修改时的状态转移。
