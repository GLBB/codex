# Threat Model：攻击者如何利用 Agent

## 用资产和路径思考

Threat Model 不是罗列吓人的攻击名称，而是回答：要保护什么、攻击者能控制什么、系统会把什么传到哪里、失败会造成什么影响。

| 资产 | 入口 | 可能结果 | 首要控制 |
| --- | --- | --- | --- |
| Secret、Token | Prompt、环境、Tool 参数 | 凭据泄露 | 运行时注入、脱敏、最小 Scope |
| 源码和客户资料 | 文件、RAG、网络请求 | 数据外传 | 数据流策略、域名白名单、最小披露 |
| 工作区与生产系统 | Shell、API、MCP | 修改、删除、发布 | Policy、Approval、隔离 |
| Agent 预算和服务可用性 | 无界循环、巨型结果 | 费用或拒绝服务 | 超时、大小、并发和预算上限 |

## 三个入门威胁

### Prompt Injection

不可信内容诱导 Agent 忽略任务、泄露信息或调用危险工具。防护重点是保持来源标记、把资料当数据、限制可用工具，并在每次副作用前重新检查权限。

### Exfiltration

Agent 把本不应离开边界的数据放入 URL、请求体、命令参数、日志或模型上下文。不能只检查“用户有没有要求上传”，还要检查字段、目的地、接收者和凭据 Scope。

### Supply Chain

工具 Server、插件、依赖包、容器镜像或更新渠道被替换或投毒。固定版本不等于可信，但能让审查、回滚和取证成为可能；还需要来源验证、签名或校验、安装审批和隔离运行。

## 实践

写三条恶意资料：一条要求泄露 Token，一条要求访问不相关目录，一条要求把结果发往外部域名。对每条标出触发的工具、应被哪项 Policy 拦截、是否需要 Approval、审计中应留下什么证据。不要真的执行这些动作。
